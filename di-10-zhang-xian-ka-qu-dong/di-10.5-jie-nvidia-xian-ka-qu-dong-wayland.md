# 10.5 NVIDIA 显卡驱动（Wayland）

## NVIDIA 显卡驱动概述

截至 2026 年 11 月，FreeBSD 上仅有两个 NVIDIA 官方驱动版本系列提供 nvidia-drm 内核模块，可用于 Wayland：

- 580.x 版本，[支持 GPU 型号](https://www.nvidia.cn/drivers/details/281524/)（在页面上点击“产品支持列表”），覆盖 Maxwell 至 Blackwell 架构，例如 GeForce 10xx 系列。
- 620.x 版本（当前为 620.73.04），[支持 GPU 型号](https://www.nvidia.cn/drivers/details/285557/)（在页面上点击“产品支持列表”），覆盖 Turing 至 Blackwell 架构，例如 GeForce RTX 30xx 系列、GeForce RTX 50xx 系列。

两者的区别在于架构覆盖范围：580.x 为长期支持分支，同时支持较老的 Maxwell、Pascal、Volta 架构；620.x 为当前主线分支，仅支持 Turing 及更新的架构。因此，Maxwell、Pascal 与 Volta 架构的显卡（如 GeForce 10xx 系列）应选择 580.x；Turing 及更新架构的显卡（如 GeForce 16xx、RTX 30xx 系列）两者均可；Kepler 及更早架构的显卡两个分支均不支持。

需注意，较老型号系列中仅部分型号受支持，应仔细阅读上述清单。部分型号的支持情况如下，✅ 表示支持，❌ 表示不支持：

| GPU 型号 | 580.x | 620.x |
| :------- | :---: | :---: |
| GeForce GTX 1650 | ✅ | ✅ |
| GeForce GTX 1660 | ✅ | ✅ |
| GeForce RTX 3050 | ✅ | ✅ |
| GeForce RTX 3060 | ✅ | ✅ |
| GeForce GTX 750 Ti | ✅ | ❌ |
| GeForce GTX 750 | ✅ | ❌ |
| GeForce GTX 745 | ✅ | ❌ |
| GeForce GTX 980 Ti | ✅ | ❌ |
| GeForce GTX 980 | ✅ | ❌ |
| GeForce GTX 970 | ✅ | ❌ |
| GeForce GTX 960 | ✅ | ❌ |
| GeForce GTX 950 | ✅ | ❌ |
| GeForce GT 1030 | ✅ | ❌ |
| GeForce GTX 1060 | ✅ | ❌ |
| GeForce GT 740 | ❌ | ❌ |

| GeForce 920M | ❌ | ❌ |

上表按支持情况分组：前四款为 Turing 与 Ampere 架构，两者均支持；中间十款为 Maxwell 与 Pascal 架构，仅 580.x 支持；末五款为 Kepler 及更早架构，两者均不支持。部分型号存在多种架构版本，实际支持情况以 NVIDIA 官方支持列表为准。

如对衍生型号的支持情况不确定，可分别安装上述两个版本系列的驱动进行实测。

## 加入 video 组

将指定用户加入 video 组，以便访问显卡设备：

```sh
# pw groupmod video -m 用户名
```

将“用户名”替换为实际用户名。

## 安装显卡驱动

使用 pkg 安装 580.x 版本：

```sh
# pkg install nvidia-drm-kmod-580 nvidia-settings
```

或使用 Ports 安装 580.x 版本：

```sh
# cd /usr/ports/graphics/nvidia-drm-kmod-580/ && make install clean
# cd /usr/ports/x11/nvidia-settings/ && make install clean
```

使用 pkg 安装 620.x 版本：

```sh
# pkg install nvidia-drm-kmod nvidia-settings
```

或使用 Ports 安装 620.x 版本：

```sh
# cd /usr/ports/graphics/nvidia-drm-kmod/ && make install clean
# cd /usr/ports/x11/nvidia-settings/ && make install clean
```

`graphics/nvidia-drm-kmod` 的默认版本当前为 620.73.04；`graphics/nvidia-drm-kmod-580` 对应 580.x 分支。两者均会自动安装与 FreeBSD 版本匹配的 nvidia-drm 内核模块及用户态驱动。

## 配置 NVIDIA 显卡驱动

> **注意**
>
> 不具备显卡直通能力（无 MUX）的笔记本，显示输出由核芯显卡驱动。此类设备须先按 10.2 节或 10.3 节配置 Intel/AMD 核芯显卡的 DRM 驱动，再执行本节步骤，否则 Wayland 可能找不到可用的显示设备。

### 启动 NVIDIA 相关内核模块

执行以下命令配置 NVIDIA 内核模块：

```sh
# sysrc -f /boot/loader.conf hw.nvidiadrm.modeset=1  # 启用 NVIDIA DRM 模式设置
# sysrc -f /etc/rc.conf kld_list+=nvidia-drm         # 加载 nvidia-drm 内核模块
```

> **警告**
>
> 上述配置将 `nvidia-drm` 设为每次启动时加载，仅适用于 Wayland 会话。10.4 节已指出，X11 用户加载 `nvidia-drm.ko` 可能导致系统崩溃。若需在同一系统中使用 X11，请勿将 `nvidia-drm` 加入 `kld_list`，可改为进入 Wayland 会话前手动执行 `kldload nvidia-drm`。

如需撤销持久加载，执行：

```sh
# sysrc -f /etc/rc.conf kld_list-=nvidia-drm
```

## 验证安装

重启 FreeBSD，验证 NVIDIA GPU 驱动是否正常加载。

若配置成功，可看到以下内核消息：

```sh
nvidia0: <NVIDIA GeForce XXXX> on vgapci0
vgapci0: child nvidia0 requested pci_enable_io
vgapci0: child nvidia0 requested pci_enable_io
nvidia-modeset: Loading NVIDIA Kernel Mode Setting Driver for UNIX platforms  580.178.04  Tue Jul  7 12:04:34 UTC 2026
[drm] [nvidia-drm] [GPU ID 0x00000100] Loading driver
sysctl_add_oid: can't re-use a leaf (hw.dri.debug)!
[drm] Initialized nvidia-drm 0.0.0 for nvidia0 on minor 0
```

若所安装的驱动不支持当前 GPU 型号，可看到以下内核消息：

```sh
NVRM: The NVIDIA NVIDIA GeForce XXXX GPU installed in this system is
NVRM:  supported through the NVIDIA 580.xx Legacy drivers. Please
NVRM:  visit http://www.nvidia.com/object/unix.html for more
NVRM:  information.  The 615.71.09 NVIDIA driver will ignore
NVRM:  this GPU.  Continuing probe...
nvidia-modeset: Loading NVIDIA Kernel Mode Setting Driver for UNIX platforms  615.71.09  Fri Sep  4 21:13:40 UTC 2026
```

上述内核消息中的版本号随驱动更新而变化，以实际安装的版本为准。

## 其他配置

硬件加速解码、驱动状态查看、驱动卸载与锁定等其他配置，可参考 10.4 节。

580.x 用户锁定驱动：

```sh
# pkg lock nvidia-drm-kmod-580 nvidia-driver-580 nvidia-settings
```

卸载驱动前须先解锁，并移除 `kld_list` 中的模块条目：

```sh
# pkg unlock nvidia-drm-kmod-580 nvidia-driver-580 nvidia-settings
# pkg delete nvidia-drm-kmod-580 nvidia-driver-580 nvidia-settings
# sysrc -f /etc/rc.conf kld_list-=nvidia-drm
```

620.x 用户沿用 10.4 节的包名即可。

## 故障排除

以下内容基于 KDE Plasma 6.8.3 与 Chromium 158.0.8127.36（2026 年 11 月 FreeBSD Ports 中的版本）。

### KDE Plasma 鼠标光标消失

表现为 KDE Plasma 启动数秒后鼠标光标消失；大幅度向左前方移动鼠标时，光标短暂出现在显示器左上角，随后再次消失。

临时解决方法是禁用硬件光标，改用软件光标。例如，KDE Plasma 启动脚本 `kde.sh` 可写为：

```sh
#!/bin/sh

# 使用软件渲染的鼠标光标
export KWIN_FORCE_SW_CURSOR=1

dbus-launch ck-launch-session startplasma-wayland
```

其中 `ck-launch-session` 由 consolekit2 提供。

KDE 官方文档指出，`KWIN_FORCE_SW_CURSOR` 仅建议用于调试，常规使用硬件光标可获得更好的性能。

### Chromium 窗口闪烁或网页崩溃

Chromium 在 Wayland 会话下可能出现窗口闪烁，打开视频网站（如哔哩哔哩）时容易发生网页崩溃。

临时解决方法是让 Chromium 使用 X11 Ozone 后端，而非 Wayland 后端。仅设置 `XDG_SESSION_TYPE=x11` 不足以覆盖 Chromium 的后端选择，须同时传入 `--ozone-platform=x11`。应用此方法前，须先完全退出所有 Chromium 进程，否则新的启动请求会被转发给已在 Wayland 下运行的实例，后端不会切换。

为免与普通 Chromium 实例共用配置文件而产生启动竞争，可为变通方案指定独立的配置目录。例如，Chromium 的启动脚本 `chrome.sh` 可写为：

```sh
#!/bin/sh

# 切换到 X11 模式，并强制使用 X11 Ozone 后端
export XDG_SESSION_TYPE=x11

chrome --ozone-platform=x11 --user-data-dir="$HOME/.config/chromium-x11" "$@" &
```

该配置目录独立于默认配置，原有书签与登录状态不会自动继承；如不需要隔离，也可省略 `--user-data-dir`，但须确保启动前没有其他 Chromium 实例在运行。

> **警告**
>
> 使用 X11 后端时，Chromium 作为 X11 客户端接入 Xwayland，可与其他 X11 客户端互相访问窗口与输入，失去 Wayland 提供的会话隔离。仅在可接受这一安全权衡时使用本方法。
